# テスト設計書：発話の逐語表示・沈黙時の平易化・画面スリープ防止

最終更新: 2026-08-25 / 対象仕様: [`docs/spec/conversation-display-spec.md`](../spec/conversation-display-spec.md)

## 1. テスト観点

| ID群 | 観点 | 種別 |
|---|---|---|
| A | 発話が書き換えられずに表示されるか | 単体（DOM） |
| B | システムプロンプトが逐語訳を指示しているか | 単体（文字列） |
| C | 沈黙時に段階的に易しくなるか | 単体（APIスタブ） |
| D | APIエラーが正しく日本語化されるか | 単体 |
| E | 画面スリープ防止が正しく動くか | 単体（APIスタブ） |

## 2. テストケース

### A. 発話表示（`fillUserFeedback`）

| ID | ケース | 期待結果 | 種別 |
|---|---|---|---|
| A1 | 補正案がある発話を表示 | `.cap-en` が**認識結果のまま**である | 正常 |
| A2 | 日本語訳を渡す | `.cap-jp` に逐語訳が出る | 正常 |
| A3 | 補正案を渡す | `.cap-suggest` に「💬 もしかして: …」が出る（主表示を奪わない） | 正常 |
| A4 | 補正案が元と異なる | 変更語が `.cap-diff` で強調される | 正常 |
| A5 | 発音ヒントを渡す | `.cap-tip` に出る | 正常 |
| A6 | 全要素が揃う | 順序が 発話→直訳→提案→ヒント である | 正常 |
| A7 | 補正案が元と同一（大文字小文字・空白のみ差） | 提案を出さない。`sessionCorrections` に積まない | 異常 |
| A8 | 補正案が空／null | 提案を出さない | 異常 |
| A9 | 日本語訳が空 | `.cap-jp` を作らない | 異常 |
| A10 | 発話・補正・ヒントにHTMLタグが混入 | タグが要素化されず、発話はそのまま文字列として保持される | 異常（XSS） |
| A11 | 同じ発話に対し2回呼ばれる | 要素が重複しない | 異常 |
| A12 | 対象の吹き出しが存在しない状態で呼ぶ | 例外を投げず何もしない | 異常 |

### B. システムプロンプト

| ID | ケース | 期待結果 |
|---|---|---|
| B1 | 逐語訳ルールが含まれる | `MUST be a LITERAL translation` を含む |
| B2 | 旧・意訳ルールが削除されている | `translate what you THINK they meant` を**含まない** |
| B3 | 返答は文脈で解釈する指示が残っている | `let your own reply respond to that intended meaning` を含む |
| B4 | 沈黙もレベル降下の根拠に含む | `or silence), drop down a level` を含む |

> B2 は再発防止の要。逐語訳ルールを足しても、旧ルールが残っていると指示が矛盾する。

### C. 沈黙時の段階的な平易化（`teacherProactiveMessage`）

APIは `window.fetch` をスタブ化して送信内容を捕捉する。

| ID | ケース | 期待結果 | 種別 |
|---|---|---|---|
| C1 | 3回連続で沈黙 | 3回とも異なる指示が送られる | 正常 |
| C2 | 1回目の沈黙 | 「より簡単な語で言い換えよ」かつ「話題を変えるな」 | 正常 |
| C3 | 2回目の沈黙 | 「さらに1段階易しく」かつ「まだ話題を変えるな」 | 正常 |
| C4 | 3回目の沈黙 | 「より易しい話題へ切り替えよ」 | 正常 |
| C5 | 学習者が発話 | `_stallCount` が 0 に戻る | 正常 |
| C6 | 4回目以降の沈黙 | 3回目と同じ指示（際限なく分岐しない） | 異常 |

### D. APIエラー変換（`explainApiError`）

| ID | 入力 | 期待する `short` | 種別 |
|---|---|---|---|
| D1 | `Request had invalid authentication credentials` | APIキーが無効です（401） | 異常 |
| D2 | `API key not valid` | APIキーが無効です | 異常（回帰） |
| D3 | `HTTP 429` | API利用上限に達しました… | 異常（回帰） |
| D4 | `PERMISSION_DENIED` | アクセス権限エラー | 異常（回帰） |
| D5 | `Failed to fetch` | ネットワークエラー | 異常（回帰） |
| D6 | `HTTP 503` | サーバー一時エラー | 異常（回帰） |

> D2〜D6 は D1 の分岐追加で既存分岐が壊れていないことを確認する回帰テスト。
> 分岐は上から順に評価されるため、挿入位置によって既存の判定が奪われうる。

### E. 画面スリープ防止

`navigator.wakeLock` をスタブ化して検証する。

| ID | ケース | 期待結果 | 種別 |
|---|---|---|---|
| E1 | 関数が定義されている | `acquireWakeLock` / `releaseWakeLock` が関数 | 正常 |
| E2 | ブラウザが対応している | `'wakeLock' in navigator` が true | 正常 |
| E3 | 取得 | `_wakeLock` が設定され、`request` が1回呼ばれる | 正常 |
| E4 | 保持中に再取得 | `request` を重ねて呼ばない（冪等） | 正常 |
| E5 | 解放 | `_wakeLock` が null になる | 正常 |
| E6 | 解放済みを再度解放 | 例外を投げない | 異常 |
| E7 | 通話中に可視へ復帰 | 自動で取り直す | 正常 |
| E8 | 通話中でないときに可視へ復帰 | 取得しない（無駄なバッテリー消費を防ぐ） | 異常 |
| E9 | 非対応端末（`wakeLock` 不在） | 例外を投げず false を返す | 異常 |
| E10 | ページが非表示で取得失敗 | 例外を投げず false を返し、**案内トーストを出さない** | 異常 |

> E10 は実装の落とし穴。`NotAllowedError` は「非対応」ではなく「今は取得できない」の意味。
> 区別しないと、対応端末でも誤って「非対応」と案内してしまう。

## 3. E2Eテストについて

CLAUDE.md はブラウザ操作を含むE2Eの自動化を求めているが、本アプリは
**マイク入力・音声認識・実APIを伴う**ため、Playwright での完全自動化には
音声のモックとAPIキーの扱いという別課題がある。

現時点では、上記の単体テストをブラウザ実機（Chrome）上のページコンテキストで実行し、
`docs/test_results/` に結果を記録する方式を採る。E2E自動化は今後の課題とする。

## 4. 手動確認が必要な項目

自動テストで担保できないため、実機での確認を要する。

| ID | 項目 | 端末 |
|---|---|---|
| M1 | 通話中、無操作で画面が消えないこと（5分以上） | Android実機 |
| M2 | 他アプリへ切替→復帰後も画面が消えないこと | Android実機 |
| M3 | 通話終了後は通常どおり画面が消えること | Android実機 |
| M4 | 実際の会話で発話が書き換わらないこと | Android実機 |
| M5 | 黙っていると教師が易しく言い換えること | Android実機 |
